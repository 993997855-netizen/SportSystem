# SportSystem 青训管家

面向足球俱乐部的微信小程序第一版，覆盖管理员、教练员和家长三个角色。

## 第一版已经实现

- 学员档案：孩子、家长、联系方式、健康/伤病备注、购课及剩余课时
- 班级管理：教练、训练时间、场地、班级学员
- 手机点名：到课、请假、伤病、缺勤四种状态；新点名表默认“未点名”，防止误把全班记为到课
- 自动扣课：默认到课和缺勤扣 1 节，请假和伤病不扣；重复保存会校正差额
- 家长查看：仅查看绑定孩子、剩余课时和出勤记录
- 续费闭环：家长提交续费申请，管理员确认到账后自动增加课时
- 身份隔离：云端模式下，管理员通过一次性邀请码绑定家长与教练
- 首页统计：学员数、班级数、低课时人数、待确认续费

> 当前续费是“提交申请 + 后台确认”的业务闭环。真实微信支付需要小程序认证、微信支付商户号、商户 API 证书和支付回调，不能只靠前端代码完成。

## 直接预览（不部署云端）

1. 用微信开发者工具导入本目录。
2. 点击“编译”。
3. 项目默认使用本地演示数据，可直接录入、点名、续费。
4. 在“我的”页面切换管理员、教练员和家长视角。

本地模式的数据只保存在当前开发者工具或手机中，适合看效果，不适合正式运营。

## 启用多人共享的云端模式

1. 在微信开发者工具中开通云开发环境。
2. 将云环境 ID 填入 `miniprogram/app.js` 的 `globalData.env`。
3. 右键 `cloudfunctions/clubApi`，选择“上传并部署：云端安装依赖”。
4. 在云开发数据库权限中，将以下集合设置为“仅云函数可读写”：
   - `users`
   - `students`
   - `classes`
   - `attendance`
   - `renewals`
   - `invites`
5. 第一个进入云端模式的微信账号会成为管理员。
6. 管理员创建学员和班级后：
   - 在学员详情生成家长邀请码；
   - 在班级页生成教练邀请码；
   - 家长或教练在“我的”页面输入邀请码完成绑定。

集合可由 `clubApi` 首次运行时自动创建。如果云环境禁止自动创建，请在控制台按上述名称手动创建。

> 创建云环境后应先由俱乐部管理员本人打开小程序完成初始化，再邀请其他账号。不要先把未初始化的体验版二维码公开，否则第一个访问者可能成为管理员。

## 关键业务规则

扣课规则集中定义在：

- 本地演示：`miniprogram/utils/local-service.js`
- 云端正式：`cloudfunctions/clubApi/index.js` 中的 `DEDUCTION`

目前规则为：

| 状态 | 扣课 |
| --- | ---: |
| 到课 | 1节 |
| 请假 | 0节 |
| 伤病 | 0节 |
| 缺勤 | 1节 |

正式上线前应由俱乐部确认请假时限、伤病证明和缺勤扣课规则，再统一调整，避免口径不一致。

为保证课时账目可追溯，学员建档后不能从档案编辑页直接修改累计购课和剩余课时；变化必须来自点名或续费。续费套餐的课时和金额也由云函数按套餐编号校验，不采用前端上传的金额。

## 数据安全说明

- 小程序前端不直接读写数据库，统一经过 `clubApi` 鉴权。
- 管理员可查看全部数据；教练只能查看所带班级；家长只能查看绑定孩子。
- 不要把手机号、商户密钥、API 证书写进小程序前端。
- 第一版暂未包含数据导出、操作审计、退款和财务对账，上线收款前需要补齐。
