# 班级与精英队 V3 开发报告

## 页面变更

已修改班级列表、班级表单、学员表单、学员详情、课程列表、课程详情、首页、请假审核、CRM 转正式学员和运营后台。班级表单负责班级属性，学员档案与编班正式拆分；家长可浏览班级，普通班未满时可为已绑定孩子报名，精英队始终显示俱乐部选拔制。

新增页面：

- `class-detail`：班级容量、成员、历史成员和管理入口。
- `class-member-add`：按姓名、家长、手机号、出生年份、当前班级搜索并人工编班。
- `class-member-transfer`：转班或调整梯队，可选择保留原班。
- `elite-action`：管理员直接晋升、教练提交推荐。
- `elite-selections`：推荐历史和管理员审核。

## 数据结构

`classes` 新增 `classType`、`ageGroup`、`standardCapacity`、`headCoachName`、`assistantCoachName`、`status`、`remark`。班级类型为 `REGULAR` 或 `ELITE`。

`classMembers` 成为正式班级关系来源，保存班级、学员、成员类型、状态、入队时间、来源、原班级、选拔记录及退出信息。同一学员可以同时拥有多个 `ACTIVE` 关系。旧 `student.classIds` 与 `class.studentIds` 在迁移和关键操作后同步保留，供旧页面和旧数据兼容。

`eliteSelections` 保存每次推荐及审核历史，状态为 `PENDING`、`APPROVED`、`REJECTED` 或 `WITHDRAWN`，不会覆盖旧记录。

## 容量与权限

- 家长：普通班达到标准容量后硬性停止报名；不能加入精英队；不能转班、晋升或修改成员关系。
- 管理员：容量为软限制。达到容量时接口先返回二次确认信息，确认后允许加入第 21 人及以后成员。
- 教练：只可查看负责班级并推荐本班学员，不能批准推荐、超额编班或移出队员。
- 管理员批准推荐或直接晋升时，可选择保留原普通班或将原关系转为 `INACTIVE`。

创建班级、修改班级类型、人工添加、超容量添加、转班、推荐、审核、晋升和移出均写入 `auditLogs`，记录操作人、学员、来源班、目标班、原因和时间。

## 历史排队数据兼容处理（已被固定班级成员制替代）

- 旧集合仅保留历史数据，不删除旧记录。
- 新的普通班报名不再创建排队记录。
- 家长端、管理端和运营后台均不再显示旧排队入口或指标。
- 自动转正函数及其调用链已经移除。
