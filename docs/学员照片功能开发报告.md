# 学员照片功能开发报告

## 实现结果

- `students.avatarUrl` 作为孩子本人照片字段，与家长微信头像、身份证资料完全分离。
- 家长新增孩子、管理员新建学员、CRM 转正式学员时，孩子照片均为必填。
- 图片通过微信云存储上传，数据库仅保存 `fileID`/文件地址，不保存 Base64。
- 家长和管理员可以替换照片；替换只更新 `avatarUrl`，不会改变学员 ID、归属、班级、课时、成长档案或赛事记录。
- 照片替换写入 `UPDATE_STUDENT_AVATAR` 审计日志。

## 页面覆盖

真实照片已经接入以下场景，照片不存在时统一回退到姓名首字或默认头像：

- 家长端：我的孩子、孩子切换器、学员详情、课程、请假。
- 教练端：班级成员、课程应到名单、点名、训练评价、阶段测评、学员详情。
- 管理端：学员列表、学员详情、班级成员、请假审批、精英队选拔、赛事名单。
- 成长系统：成长档案、阶段测评、比赛记录。
- 招生系统：CRM 转正式学员。

管理员学员列表会对历史缺少照片的档案显示“照片未完善”，不会因旧数据缺失导致页面报错。

## 权限与隐私

- 家长端后端校验以 `student.ownerParentUserId === currentUser._id` 为准，不能读取或修改其他家庭孩子的照片。
- 教练只能通过授权班级、课程或球队读取所管理学员的照片。
- 管理员可以读取和替换全部学员照片。
- 未建立公开照片库，也没有把内部学员照片自动用于新闻、宣传或明星学员展示。
- 身份证号码继续保存在 `studentPrivateProfiles`，不随 `students` 日常接口返回；照片和身份证权限边界没有混用。

## 云存储约定

上传目录：

```text
student-photos/internal/YYYY-MM-DD/<timestamp>-<random>.<ext>
```

正式环境需保持微信云开发存储权限为非公开写入，并通过业务接口控制学员资料访问。

## 回归验收

新增 `tests/student-photo-regression.js`，覆盖 13 项：必填校验、上传地址保存、刷新持久化、家长列表、管理员列表、班级成员、点名、成长档案、赛事名单、家长替换、管理员替换及审计、跨家长越权阻断、缺图回退和禁止 Base64。

本地全部回归测试通过，包括家长唯一归属、身份证隐私、CRM、固定班级、请假、课时、成长档案、阶段测评和周日成长联赛。
