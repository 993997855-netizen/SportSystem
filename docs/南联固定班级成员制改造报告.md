# 南联固定班级成员制改造报告

## 1. 已移除哪些候补功能

- 家长端的排队入口、排位状态和相关按钮。
- 课程详情中的历史排队名单展示。
- 运营后台中的排队人数指标。
- 本地与云端的自动补位函数，以及由请假、退班等行为触发自动补人的可能性。
- 新业务对旧排队集合的查询和写入。

## 2. 哪些 waitlist 历史逻辑仍保留

- 云数据库集合名仍保留，避免现有历史数据因升级被删除或导致旧环境初始化失败。
- 本地演示种子保留一条带 `legacy: true` 的历史记录，用于验证升级不会改写旧数据。
- 历史数据只读保留，不在新页面展示，也不会被转正、排序或用于容量计算。

## 3. 哪些页面删除了候补入口

- 首页近期课程。
- 课程列表与课程详情。
- 个人中心课程入口。
- 运营驾驶舱。
- 班级详情统一显示“正式成员名单”，不再拆分其他名单。

## 4. 家长满员报名现在如何处理

普通班的 ACTIVE `classMembers` 达到 `standardCapacity` 后返回 `FULL`，页面显示“本班已满”，不创建任何排队记录。精英队仍为选拔制，家长不能自主报名。

## 5. 管理员超标准人数如何添加

管理员第一次添加时收到当前人数、标准人数和添加后人数的二次确认提示。确认后允许直接创建 ACTIVE `classMember`，并显示超出标准人数；标准人数不作为管理员的绝对上限。

## 6. classMembers 现在是不是班级成员唯一权威来源

YES。班级人数、课程正式应到名单、请假资格、点名权限和教练反馈名单都从 ACTIVE `classMembers` 读取。旧 `student.classIds`、`class.studentIds` 仅作为兼容镜像，不参与权威判断。

## 7. 请假是否改变班级人数

NO。批准请假只写入本节 `attendance = leave`，扣课为 0。

## 8. 请假是否触发候补

NO。系统已不存在自动补位函数和调用链。

## 9. 退出班级是否自动补人

NO。管理员明确移出后只把原成员关系改为 `INACTIVE`，记录 `leftAt`、`leftBy`、`leaveReason`，不会加入其他学员。
