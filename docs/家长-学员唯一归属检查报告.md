## 二、唯一归属规则如何实现

### 1. 权威字段

每个学员使用：

```js
student.ownerParentUserId
```

作为唯一权威家长归属。一名家长可以被多个 Student 引用，但每个 Student 只能保存一个 `ownerParentUserId`。

### 2. users.studentIds 兼容方式

`users.studentIds` 继续保留，作为旧页面和旧数据的兼容缓存，不再用于最终授权。新增孩子、审核绑定、邀请码领取和管理员转移归属后，会依据 `students.ownerParentUserId` 重新生成相关家长的 `studentIds`。

即使有人错误地把同一个 studentId 写进另一个家长的 `users.studentIds`，后端读取学员、课程、请假、课时、成长和赛事时仍会检查 `student.ownerParentUserId === currentUser._id`，错误缓存不会产生访问权限。

### 3. parentStudentLinks 兼容方式

该集合不再承担多对多关系。新写入时业务层会检查同一 `studentId` 是否已有其他 ACTIVE 家长关系。管理员正常转移时，原 ACTIVE 记录变为 `TRANSFERRED`，再创建目标家长的唯一 ACTIVE 记录。

历史数据如果已经存在多个 ACTIVE 家长关系，不会自动选择或删除其中一个，而是输出 `DUPLICATE_PARENT_BINDING` 并标记“需要管理员人工确认”。

## 三、身份证唯一性

- 完整身份证保存在 `studentPrivateProfiles`，不进入普通 `students`。
- 家长提交前执行18位格式、出生日期和校验位检查。
- 通过 `studentPrivateProfiles.idCardNumber` 查找已存在学员。
- 同身份证已属于当前家长时，提示无需重复添加。
- 同身份证已属于其他家长时，提示“该学员已经绑定家长账号，请联系俱乐部管理员处理”。
- 同身份证已有学员但尚无家长归属时，只允许提交审核绑定，禁止创建第二个 Student。
- 管理员审核新建前再次查重，发现已有身份证即拒绝重复创建。

正式环境应为 `studentPrivateProfiles.idCardNumber` 建唯一索引，并把“最终查重—创建学员—写入私密档案”放在事务或等效的原子流程中。

## 四、管理员转移家长归属

管理员从学员详情进入“家长账号归属”，选择目标家长并填写转移原因。系统先返回确认信息：

```text
该学员当前归属家长：王先生
确定要将学员转移至：李女士？
转移以后原家长将无法继续查看该学员资料。
```

确认后执行：

1. 将原 ACTIVE 兼容关系标记为 `TRANSFERRED`。
2. 修改 `student.ownerParentUserId`。
3. 建立目标家长唯一 ACTIVE 兼容关系。
4. 重新同步新旧家长的 `users.studentIds`。
5. 写入 `TRANSFER_STUDENT_PARENT` 审计记录，包括 `studentId`、`oldParentUserId`、`newParentUserId`、`operatorId`、`reason` 和时间。

转移完成后，旧家长对基本资料、课程、课时、请假、考勤、成长档案和赛事的后端权限立即失效；新家长获得权限。

## 五、邀请绑定检查

- 管理员不能为已有 `ownerParentUserId` 的学员创建新的家长邀请码。
- 家长领取邀请码时，在云数据库事务中重新读取 Student。
- 如果 Student 已属于其他家长，事务拒绝绑定。
- 邀请成功后写入 `ownerParentUserId`，再同步 `users.studentIds`。

## 六、冲突检查器

管理员接口：

```text
checkParentOwnershipConsistency
```

同时扫描：

- `students.ownerParentUserId`
- 所有 Parent 的 `users.studentIds`
- `parentStudentLinks` 中 ACTIVE 关系

若同一 studentId 出现两个及以上不同 parentUserId，输出：

```text
DUPLICATE_PARENT_BINDING
```

报告包含学员姓名、studentId、涉及家长、数据来源、绑定时间和“需要管理员人工确认”。检查器的 `autoFixed` 永远为 `false`。

## 七、回归验证

新增唯一归属专项回归 12 项，覆盖：

1. Parent A 添加 Student A。
2. Parent A 再添加 Student B。
3. Parent B 直接绑定 Student A 被拒绝。
4. Parent B 使用 Student A 身份证重复创建被拒绝。
5. 管理员转移前返回明确二次确认。
6. 管理员确认转移成功并同步双方缓存。
7. Parent A 转移后失去基本资料和成长档案权限。
8. Parent B 转移后获得权限。
9. 修改 API studentId 越权访问课时和课程被拒绝。
10. 转移审计字段完整。
11. 同一 Student 只有一个 ACTIVE 兼容关系。
12. 冲突扫描能报告且绝不自动修复历史冲突。
