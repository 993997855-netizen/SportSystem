# 南联统一课表系统开发报告

## 0. 当前程序架构说明

当前代码仓库只有一个微信小程序工程和一个 `clubApi` 云函数，没有独立的 Web/PC 管理平台工程。原项目所称“管理平台”是同一小程序内按管理员权限开放的“南联运营后台”。本轮在这一真实架构上同步建设管理员端、教练端和家长端，三端共用同一云函数及数据源；没有虚构第二套后台或不安全的 Web 管理员登录。

## 1. 两个使用端分别修改了哪些页面

### 管理平台（现有管理员运营端）

- 管理员首页：新增“总课表”、今日课程和下一课程入口；
- 运营后台：快捷入口改为“南联总课表”；
- 南联课程总表：提供上一周、本周、下一周、日期选择，支持按时间、教练、班级、场地四种视角；
- 总课表筛选：支持普通班、精英队、指定班级、指定教练和指定场地；
- 冲突汇总：显示教练、班级、场地冲突数量，点击后只显示对应冲突课程；
- 课程卡片：显示班级类型、时间、场地、主教练/助教/代课、状态、训练主题和冲突标签；
- Session 详情与编辑：继续复用原页面修改时间、场地、教练、代课、点名和请假，没有建立第二套编辑页面；
- 班级表单：主教练和多个助理教练作为后续课程计划快照来源。

### 微信小程序

- 首页：管理员显示“总课表”，教练和家长显示“我的课表”；增加今日课程、下一节课或下一安排；
- 教练工作台：升级为教练个人周课表时间轴，支持上下周、今天、主教/助教/代课统计；
- 家长“我的课表”：新增当前孩子、指定孩子和全部孩子切换；
- 家长时间轴：显示训练、比赛、孩子姓名、时间、班级、实际教练、场地、主题、状态和请假状态；
- Session 详情：训练课程继续进入现有详情完成请假、点名等流程；比赛保持独立业务语义。

## 2. 三种课表是否统一读取 sessions

**YES。**

管理员训练总课表、教练训练课表和家长训练课表全部调用 `getUnifiedTimetable`，其训练数据唯一来源是 `sessions`。没有建立 `adminSchedules`、`coachSchedules` 或 `parentSchedules`。

比赛不是训练课，继续读取现有 `matches` 和 `matchSquads`，只在接口返回时聚合成日程卡片，不复制进 `sessions`，也不形成训练课时。

## 3. 管理员修改课程后是否自动同步两端

**YES。**

管理员修改 Session 的时间、场地或实际教练后，教练和家长重新进入课表会直接读取该 Session 最新值。系统不存在额外同步任务，也不存在第二份家长/教练课表缓存数据库。

## 4. 教练权限如何实现

后端以 Session 的 `actualCoachAssignments` 为优先；没有实际安排时使用 `plannedCoachAssignments`。教练只有在自己是主教练、助理教练或代课教练时才能读取该训练课程。代课调整完成后，新教练自动出现在自己的课表中，被完全替换且不再实际执教的教练不再看到该课程。

教练不能使用筛选参数越权读取其他教练完整排班。

## 5. 家长多孩子权限如何实现

后端先用 `students.ownerParentUserId === currentUser._id` 得到该家长可访问的孩子，再用 `classMembers` 的 ACTIVE 成员关系计算每个孩子应出现的训练 Session。

指定 `studentId` 时必须属于当前家长；使用 `ALL` 时仅聚合该家长自己的全部孩子。课程卡片保留 `studentId + studentName`，因此同一家庭多个孩子的安排不会混淆。

## 6. 请假课程为什么仍然存在

课表资格来自固定班级成员 `classMembers`，不是请假记录。请假只写入 `leaveRequests` 和本节 `attendance=leave`，不会删除班级成员，也不会删除 Session。

因此批准请假的课程继续显示，并标记“已请假 · 本次不扣课时”。系统没有候补转正或请假补位逻辑。

## 7. 成长联赛如何进入日程

现有南联周日成长联赛继续使用 `matches`、`matchSquads` 和 `teams`。孩子进入比赛名单后，统一课表接口把该比赛聚合为 `sourceType=MATCH` 的日程项，显示比赛时间、集合信息、场地、对阵和带队教练。

比赛项固定 `lessonDeduction=0`，不会写训练考勤或 `lessonLedger`。正式云端需已有比赛及名单数据才会显示，本轮不会向正式环境自动写入虚假比赛。

## 8. 冲突如何检测

系统在同一天对 Session 时间区间做两两交叉检查，并分别识别：

- 同一教练同时出现在两节实际/计划课程；
- 同一班级存在重叠课程；
- 同一场地存在重叠课程。

总课表返回冲突对数量并给相关课程加标签。系统只提示，不自动换时间、场地、教练或删除课程。发布和代课阶段仍沿用原有“管理员确认 + 强制原因 + Audit Log”流程。

## 9. 新增数据字段

训练 Session 继续兼容现有 `time`、`venue`、`focus`，没有为了课表重复建模。统一接口会派生 `startTime`、`endTime`、`venueId`、`trainingTheme` 和 `trainingFocus` 视图字段。

Session 可增量保存以下可选字段：

- `venueId`；
- `trainingTheme`；
- `trainingFocus`；
- `publishStatus`。

教练字段继续复用上一阶段的 `plannedCoachAssignments` 和 `actualCoachAssignments`，历史课程不会根据当前班级主教练动态覆盖。

## 10. 是否新建重复课表数据库

**NO。**

没有创建管理员、教练或家长专用课表集合。`matches`、`matchSquads`、`teams` 是比赛业务实体，不是训练课表副本。

## 11. Demo 测试步骤

1. 以管理员进入“首页 → 总课表”，查看本周 15 节以上课程及冲突统计；
2. 切换按时间、按教练、按班级和按场地；
3. 点击训练课程进入原 Session 详情，更换吴教练代课；
4. 切换吴教练，进入“我的课表”，确认显示该课程及“代课”；
5. 切换家长，进入“我的课表”，选择单个孩子或“全部孩子”，确认课程显示吴教练；
6. 批准孩子请假，确认课程仍显示且标记不扣课时；
7. 查看 2026-08-23 所在周，确认比赛进入日程且不产生训练课时；
8. 取消课程，确认三个端保留记录并显示“已取消”。

本地演示包含 4 名教练、5 个班级、2 个主要场地、一个多孩子家庭、15 节以上训练课、代课、取消、请假、比赛和冲突数据。
