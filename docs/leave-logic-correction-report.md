# 请假逻辑增量修正报告

## 修正结论

请假现在只影响指定课程场次的考勤状态，不再改变班级成员、课程报名、课程容量或历史候补记录。管理员批准后，该学员仍留在当次课程的应到名单中，考勤标记为 `leave`，扣课时为 0。

项目继续沿用现有小写状态值以兼容历史数据：`present`、`leave`、`sick`、`absent`、`unmarked`。其中界面将 `sick` 作为“伤病”统计展示。

## 业务规则

- 家长提交请假后生成 `pending` 申请；待审核阶段不改考勤、不改课时。
- 仅管理员可以批准或驳回。教练可以查看自己负责班级的请假记录，但不能审批。
- 批准后创建或更新当次考勤为 `leave`，扣课时为 0；不修改 `classMembers` 和 `enrollments`。
- 若审批前已记为到课或缺勤并扣除 1 节，审批会新增一条 `leave_correction` 流水返还 1 节，保留原扣课记录。
- 重复批准为幂等操作，不重复返还课时、不重复新增流水。
- 驳回只更新请假申请状态，不自动记缺勤。
- 家长可撤销待审核申请；已批准申请不能自行撤销，需要管理员在考勤页明确确认后修正，并写入审计日志。
- 请假不释放课程容量，不触发候补转正。历史 `waitlist` 数据和兼容函数继续保留为只读兼容能力。
- 课程统计包含应到、到课、请假、伤病、缺勤和未点名。已批准请假的学员仍显示在应到名单中，并默认锁定为“请假”。

## 数据与审计

请假申请保存学员、课程、班级、提交人、提交时间、原因、审核人、审核时间和审核意见。批准、驳回、撤销、课时返还以及人工覆盖已批准请假均写入 `auditLogs`，包含操作人、旧状态、新状态和课时变化。

考勤变更统一经过同一套课时计算：到课/缺勤扣 1 节，请假/伤病扣 0 节。所有余额变化均通过 `lessonLedger` 追加流水完成，不覆盖历史记录。

## 问题分级与处理

- P0（已解决）：旧逻辑批准请假会把课程报名从 `booked` 改为 `leave`，导致应到名单减少、容量被释放。现已彻底移除该副作用。
- P1（已解决）：旧逻辑未生成请假考勤、无法返还已扣课时，也没有重复审批保护。现已加入考勤落库、差额流水和幂等控制。
- P1（已解决）：家长端及管理端存在“请假会释放名额”的错误语义。相关按钮、提示和名单展示均已更新。
- P2（上线事项）：微信云开发正式环境部署后，需要用管理员、教练、家长真实账号完成权限验收，并按控制台提示补充组合查询索引。

## 回归结果

- 请假申请、批准、驳回、撤销、权限与容量：通过。
- 请假后报名、班级成员、精英队记录及历史候补保持不变：通过。
- 未点名、到课、缺勤、请假、伤病统计：通过。
- 缺勤转请假、到课转请假均只返还 1 节；重复审批不重复返还：通过。
- 已批准请假默认锁定，显式修正后重新计算课时并写审计：通过。

自动化回归脚本位于 `tests/leave-regression.js`。
