# 南联财务与经营系统 V6 开发报告

## 一、交付结果

本阶段已在《南联青训云端管理版》现有架构上完成财务、课包、订单、手工收款、退款、课时发放、续费预警和经营统计闭环。订单、资金和课时是三类独立数据；课时余额的所有变化仍以 `lessonLedger` 为唯一权威流水。

## 1. 产品模型

新增 `products`，保存产品名称、产品类型、课时数、售价、适用班级类型、适用年龄组、有效期、上下架状态和说明。支持 `LESSON_PACKAGE`、`SEASON_PACKAGE`、`EVENT_FEE`、`OTHER` 四种类型。管理员可以新增、编辑、改价和上下架，历史订单保留购买时的产品与价格快照，不受后续改价影响。

## 2. 订单模型

新增 `orders`，订单同时绑定 `parentUserId`、`studentId` 和 `productId`，并保存产品名称、产品类型、课时数、原价、优惠、应收、实收、退款、来源及状态。状态覆盖待付款、部分付款、已付款、已取消、部分退款和已退款。

## 3. payment 模型

新增 `payments`，每次手工收款独立记录金额、方式、交易单号、幂等键、收款人、收款时间和备注。第一阶段支持微信转账、支付宝、现金、银行转账和其他方式，不依赖微信支付回调。

## 4. refund 模型

新增 `refunds`，记录关联订单、孩子、退款金额、扣回课时数、原因、操作人和时间。退款只增加记录，不删除订单、收款或原始购课流水。

## 5. 订单如何增加课时

创建订单或部分付款均不会加课。只有累计实收达到订单应收、订单进入 `PAID` 后，系统才根据订单课时数写入一条 `PACKAGE_PURCHASE` 流水，并同步课时余额。赛事费用等零课时产品不会改变课时。

## 6. 如何防止重复加课

收款使用 `idempotencyKey` 和 `transactionRef` 检查重复请求；订单同时保存 `lessonGrantedAt` 与 `lessonLedgerId`。发课前还会检查是否已经存在相同 `orderId` 的 `PACKAGE_PURCHASE` 流水，因此重复点击、刷新或重复回调不会再次发课。

## 7. 退款如何修正课时

退款可只退金额，也可同步扣回指定课时。扣课通过新增 `REFUND_ADJUSTMENT` 负向流水完成，原 `PACKAGE_PURCHASE` 保留。若扣回后会形成负课时，服务端默认拒绝，只有管理员明确传入强制确认才允许。

## 8. 如何与 lessonLedger 打通

购课、退款、赠课、补课和人工扣课都写入 `lessonLedger`。购课与退款流水以 `referenceType: order`、`referenceId: orderId` 关联订单；订单详情反向加载全部关联流水，实现订单与课时双向追溯。系统没有提供直接覆盖课时余额的输入框。

## 9. 多孩子家庭如何区分订单

每张订单必须绑定一个具体 `studentId`。家长为王小明和王小雨购买产品时生成两张独立订单，两人的课时、退款和流水互不共享。管理员家庭视图只做分孩子汇总展示，不改变独立归属关系。

## 10. 家长权限

家长可按当前孩子查看和创建订单，但后端每次都验证真实学员归属，不能通过修改 `studentId` 或订单 ID 读取其他家庭财务信息。多孩子切换时只切换查询条件，不合并课时或订单。

## 11. 教练权限

普通教练只能查看自己权限范围内的课时不足提醒。产品价格、订单金额、累计消费、退款和支付方式均不返回给教练，也禁止教练调用订单与财务金额接口。

## 12. 管理员经营看板

经营中心显示今日收款、本月收款、本月新增订单、本月退款、待收订单及金额、即将续费学员、最近收款和最近退款。班级详情增加正式成员、本月新增、本月续费人数、低课时人数和累计实收等运营指标。

## 13. CRM 如何关联首单

线索转正式学员时可以选择产品。系统先创建零课时正式学员，再创建来源为 `CRM_FIRST_ORDER` 的待付款首单，并将 `crmLeadId` 写入订单。只有首单全额收款后才发放课时，链路为：CRM → 正式学员 → 首单 → 收款 → 课时流水 → 正式训练。

## 14. Demo 测试流程

本地演示数据包含 5 个课程产品、20 笔不同状态订单，以及已付款、部分付款、待付款、部分退款和全额退款记录；另准备至少 3 名低课时学员。可在“运营后台 → 财务与经营中心”查看看板，在“续费与订单”创建订单并进入订单详情登记收款或退款。

## 16. P0 / P1 / P2 问题

### P0：上线前必须完成

- 在微信云开发控制台创建或确认 `products`、`orders`、`payments`、`refunds`、`financeSettings` 集合，并按业务权限设置数据库规则。
- 重新上传并部署 `clubApi` 云函数，选择云端安装依赖；否则正式环境仍会使用旧接口。
- 用正式管理员、家长、教练账号分别完成一次权限验收，重点验证跨家庭订单不可读、教练不可读金额。
- 正式启用前确认历史课时余额与 `lessonLedger` 一致，禁止人工直接改数据库余额。

### P1：正式运营前建议完成

- 为 `payments.idempotencyKey`、`payments.transactionRef`、`orders.orderNo` 建立唯一索引或等效冲突保护，进一步增强并发安全。
- 为管理员补充可视化的负余额二次确认和退款审批流程。
- 完善产品适用班级/年龄的选择控件，并在下单时做强校验。
- 增加订单导出、收款对账、操作员日结和退款凭证上传。

### P2：后续经营升级

- 接入微信支付、支付回调验签与自动对账。
- 增加发票、合同、优惠券、欠费催缴和消息订阅提醒。
- 增加按校区、班型、产品、渠道和时间维度的经营分析。
- 将赛事报名费、交通费和服装费正式接入 `EVENT_FEE` 产品与订单流程。

## 云端部署说明

在微信开发者工具中打开项目根目录，进入 `cloudfunctions/clubApi`，执行“上传并部署：云端安装依赖”。部署后清除小程序缓存或重新编译，再以管理员身份进入经营中心验证产品、订单、收款、退款和课时流水。
